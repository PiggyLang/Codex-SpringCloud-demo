# 订单服务降级学习实验

这个实验演示订单服务调用用户服务失败时的手动降级：订单仍然返回，用户字段省略，并用状态和提示说明用户信息暂不可用。Feign 调用异常和成功但没有返回用户数据都会进入这个状态；其他编程错误仍会正常暴露。

这不是 Sentinel 或熔断器。当前每次请求仍会尝试调用用户服务，OpenFeign 的连接和读取超时分别配置为 1 秒和 2 秒；它们不是整个订单请求的总耗时上限。

## 本地观察

先启动 Nacos、网关、订单服务和用户服务。修改配置或代码后，重启订单服务。通过网关访问：

```text
GET http://localhost:18080/orders/1
```

正常时响应包含用户信息：

```json
{
  "orderId": 1,
  "productName": "Java 面试题",
  "user": { "id": 100, "name": "刘浪" },
  "userStatus": "AVAILABLE",
  "userMessage": "查询成功"
}
```

要观察降级，请停止用户服务的两个实例（端口 `18081` 和 `18083`），再请求同一地址。Nacos 服务发现或本地缓存可能需要一点时间更新；如果仍选到已停止的实例，连接失败也会触发降级。

```json
{
  "orderId": 1,
  "productName": "Java 面试题",
  "userStatus": "UNAVAILABLE",
  "userMessage": "用户信息暂不可用"
}
```

重新启动用户服务后再次请求，用户信息会恢复。此演示固定查询用户 `100`，没有单独的“用户不存在”状态；真实业务中，服务成功返回“用户不存在”应由业务规则决定如何展示，不应和暂时的远程服务故障混为一谈。
